cppgm is an ultra-fast C++ compiler

- **Try it.** [incpption.com](https://incpption.com) runs the compiler in a
  browser. There, cppgm compiles itself on your device.
- **Read about it.**
  [How I Built a Compiler That Is Faster Than GCC and Clang](https://medium.com/@vishvananda/how-i-built-a-compiler-that-is-faster-than-gcc-and-clang-4c8c1d4818fa)
  explains how the reference compiler was built. The origins of the proect can
  be found in the blog series that begins with
  [I Spent 2 Billion Tokens Writing a C++ Compiler So You Don't Have To](https://medium.com/@vishvananda/i-spent-2-billion-tokens-writing-a-c-compiler-so-you-dont-have-to-d3e4eec4781e).
- **Take the course.** This repository also includes instructions and tests
  that can be used as a scaffold for an agent to build its own C++ compiler with
  maximum efficiency. To try it, point your agent at
  [cppgm-assignments](https://github.com/vishvananda/cppgm-assignments). This
  export has the scaffolds, the handouts, the tests and the reference tools.
  Its references are generated by this compiler.

## Performance

Speedups compare cppgm with GCC or Clang at O3. Higher is faster. Where a cell
contains three badges, they show GitHub-hosted EPYC, GitHub-hosted Intel and
dedicated Intel, in that order. Green through red indicates the speedup, with
red at 0.50× or below. `n/m` means unmeasured and `n/a` means inapplicable.
An asterisk marks a measurement at least 10 commits behind `main` or outside
its history. At 100 commits behind, a gray `stale` badge replaces the speedup.
A gray Godot runtime badge with a dagger (`†`) means the reference binary's own
time moved by more than 5% since its last run on the same processor.
[Measurement age](https://github.com/vishvananda/cppgm/blob/benchmark-badges/freshness.md)

### Backend performance

Each backend builds the compiler, runs a SIMD workload, and runs the same
public programs. The public subset uses the original sources and inputs for
sorting, floating-point matrix multiplication, recursive search and a C++
prime sieve that uses virtual calls. Each
execution must match the same stdout checksum on all three targets. The public-subset badge shows the geometric mean of the five
CPU speedups against Clang. Click it for individual program results and the
measured revision. [Shared public workloads](benchmarks/public/README.md#shared-backend-workloads) · [Main benchmark runs](https://github.com/vishvananda/cppgm/actions/workflows/benchmark-queue.yml?query=branch%3Amain)

For native self-builds, the compile columns time building cppgm. The runtime
columns time the resulting compilers rebuilding the same sources. WASI compares
cppgm with Clang targeting WASI and runs the resulting compilers in Wasmtime.
The Wasm SIMD128 and scalar workloads time warmed exports in one engine.
Arm64 kernel timings include integer and floating-point NEON. On native Linux

## Caveats

- The [required C++11/14/17 profile](LANGUAGE_PROFILE.md) covers selected features. It is not full conformance to each edition.
- The language profile lists the supported C++20 features.
- PA38 provides experimental C support from C90 through C23, including selected GNU extensions. Library coverage depends on the target SDK. [PA38](pa38/README.md) · [Bare Wasm library](BUILDING.md#bare-wasm-c23-library-supplement) · [Hosted WASI library](BUILDING.md#hosted-wasi-c23-library-supplement) · [Coverage inventory](reports/upstream-c-coverage.md)
- The x86-64 backend targets Linux and Intel macOS. PA37 targets `wasm32-unknown-unknown` and `wasm32-wasip1`. **AArch64 support is experimental** on Linux (ELF) and Apple Silicon macOS (Mach-O) in PA39. [PA37](pa37/README.md) · [PA39](pa39/README.md)
- [PA40](pa40/README.md) is an experimental i386 Linux assignment covering ELF32 objects and x86 real-mode assembly.
- `-Oz` and the LTO flags are experimental. `-Oz` optimizes for size.
  `-flto=full` optimizes consecutive source inputs together on Wasm, Linux
  x86-64 and both AArch64 targets. On these native targets, add
  `-c -o combined.o` to write a host-linkable ELF or Mach-O object.
  On AArch64, `-flto` is shorthand for full source LTO. On Wasm, `-flto`
  shares identical function bodies when linking objects. Full LTO needs the source files
  in the same command and can use more memory. Keep competing weak and
  strong definitions in separate objects so the linker can select one.
- [Integrated assembly](pa29/README.md) is complete for its documented x86-64 profile. It is not a general assembler.
- The compiler has no C++ standard library of its own. Use the library that is installed on the host.
- The compiler can contain bugs.
- The generated code can be slow for program shapes that the benchmarks do not cover.

## Build and validate

The main target is Linux x86-64. Install a C++11 host compiler, GNU make,
Bash, Perl and Python 3. Later checks also use binutils and a debugger.

```sh
make CXX=g++ CPPGM_HOST_CXX=g++
make test-report
make inception
```

To get only the compiler, check out `dev/` without the course data and build
`cppgm`:

```sh
git clone --depth 1 --filter=blob:none --sparse https://github.com/vishvananda/cppgm.git
git -C cppgm sparse-checkout set dev
make -C cppgm/dev cppgm CXX=g++ CPPGM_HOST_CXX=g++
```

To build with Clang, pass `CXX=clang++ CPPGM_HOST_CXX=clang++`. `CC` does not
select the C++ host compiler. Use one host toolchain for a whole build.

The [releases](https://github.com/vishvananda/cppgm/releases) provide the tools
and LowIR library for Linux x86-64, Linux AArch64, Intel macOS and Apple Silicon,
plus WASI modules and two source downloads. Choose `cppgm-<tag>-source.tar.gz`
to build the tools and library, or `cppgm-<tag>-source-with-tests.tar.gz`
to build them and run the assignment suites. See
[reference and version exports](TESTING_AND_REFERENCES.md#reference-and-version-exports).

[The LowIR library guide](docs/lowir-library.md) covers object emission for
x86-64, WebAssembly and experimental AArch64 targets.

[The macOS guide](docs/intel-macos.md) describes Intel macOS support and its
optional checks.
